# ADR-000 — VOMAC v0.1 Problem Definition

## Status
Accepted (Historical)

## Problem
Modern software systems often receive data from multiple sources
but lack a structured decision-making core that can interpret inputs,
maintain internal state, and produce consistent decisions.

Most applications tightly couple logic with implementation,
making reasoning, extension, and system integration difficult.

## Goal
The goal of VOMAC v0.1 is to build a minimal but structured
decision core that can:

- Accept structured input
- Maintain internal memory/state
- Apply deterministic rule-based reasoning
- Produce a clear and traceable output

## Non-Goals (v0.1)
- Machine learning
- Natural language understanding
- Optimization or planning
- External integrations

These will be addressed in later versions.

## Input
VOMAC receives a structured input object containing:
- Source
- Type
- Payload data

Example:
```json
{
  "source": "system",
  "type": "event",
  "payload": {
    "value": 72
  }
}
```
## Output
VOMAC produces a structured decision result:

```json
{
  "decision": "ALERT",
  "reason": "Value exceeded threshold",
  "confidence": 1.0
}
```
---

## Context

Modern software systems often receive data from multiple sources
but lack a structured decision-making core capable of:

- interpreting inputs consistently
- maintaining internal state
- producing traceable decisions

Most early-stage systems tightly couple decision logic
with implementation details, making extension and reasoning difficult.

---

## Decision

VOMAC v0.1 was designed as a **deterministic decision pipeline**.

The system followed a linear flow:

Input → Memory → Reasoning → Output

This approach was selected to:

- simplify early experimentation
- validate decision logic
- ensure predictability
- minimize architectural complexity

---

## Goals

The goals of v0.1 were:

- accept structured input
- maintain internal state
- apply rule-based reasoning
- produce clear, explainable outputs

---

## Non-Goals

The following were intentionally excluded:

- machine learning
- natural language understanding
- optimization or planning
- external system integrations

These were deferred to later versions.

---

## Outcome

v0.1 successfully validated:

- deterministic reasoning logic
- configuration-based thresholds
- traceable decision outputs

However, architectural limitations were identified.

---

## Limitations Identified

- tightly coupled pipeline structure
- difficulty in extending behavior
- lack of modular isolation
- inability to support parallel or event-driven flows

These limitations directly motivated the architectural redesign
introduced in **VOMAC v0.2.0**.

---

## Conclusion

VOMAC v0.1 fulfilled its purpose as an experimental decision core.

Future versions prioritize architectural scalability
over decision complexity.
